LinBench usage guide

LinBench analyses OpenFAST linearisations with or without a ROSCO controller: open-loop modes and responses, closed-loop stability and margins, and how both change with wind speed and controller gains. It runs on your PC; the page in your browser talks to a local Python server (the console window).

Quick start

  1. Start LinBench: unzip LinBench-<version>-win64.zip on any Windows 10/11 PC and double-click LinBench.exe: nothing to install, no internet. It opens as its own window; closing the window stops LinBench, and starting it again brings the open window to the front. The first start on another PC may show Windows protected your PC (SmartScreen): More info → Run anyway. From source: python -m linbench (opens in the browser if the window engine is not installed; keep the console open). LinBench keeps to your PC: any connection other than to itself is refused. Errors are written to %USERPROFILE%\.linbench\linbench_error.log.
  2. Pick the linearisation folder (the .lin files for all wind speeds and azimuths). The table on the right lists the operating points found.
  3. For closed-loop results pick the DISCON.IN. A DISCON in the same folder, or one level up, is picked up automatically. A ROSCO tuning YAML fills in the other paths and adds the ωpc/ζpc design targets.
  4. Choose Open loop, Closed loop or Both and press Run analysis. The Run analysis page shows each step and its maths while it works.
  5. Pick an operating point with the wind-speed chips at the top (or ← →) and open the views in the list on the left, or press Ctrl K and type what you are looking for.
Try it without your own data: the folder samples/synthetic_rotor holds a synthetic 3-bladed rotor with blade DOFs and synthetic_DISCON.IN, a ROSCO-style controller tuned for it. Every screen, including the gain study, works on it. It is synthetic data, not a real turbine.

The Run analysis page

While the analysis runs you see:

  • Steps with a tick and the time each one took. Click a step to show its maths.
  • What is being computed: the equations of the current step and why the step matters.
  • Live charts, filled in point by point:
    • MBC: periodicity removed: how periodic the model is over azimuth, before and after the Coleman transform. After MBC it should drop by orders of magnitude; what is left is real rotor anisotropy.
    • Modes found: natural frequency per wind speed, coloured by damping (red = unstable). This is an early Campbell diagram.
    • Closed-loop margins: gain and phase margin per wind speed; ✕ marks an unstable closed loop.
  • Analysis log: one line per result: model size, periodicity, least-damped mode, gains, stable/unstable with the Nyquist bookkeeping (Z, P, N), margins. Unstable points are shown in red.

Results open by themselves as soon as the open-loop part is ready. The closed loop is computed afterwards, selected wind speed first; the Closed loop views in the list on the left show a counter and switch on when it is done. If you click or scroll on the page, it stays open and shows an Open results button instead. You can get back to it later from ⋯ → Analysis log in the top bar.

Repeat runs are instant. Processed results are stored in ~/.linbench/cache and reused when no .lin file changed (name, size, date). Changing any file, or updating LinBench, recomputes. Delete that folder to clear it.

Moving around

The window has four parts:

  • Top bar: ☰ (view names or icons only), the data set (its dot is the closed-loop verdict; click it for the specification sheet: headline figures, turbine constants with their source, operating range, linear model, ROSCO settings in words with their DISCON names, gain schedules, notches, input files), the search box (Ctrl K), Report (page icon), Settings (gear, Ctrl ,) and ⋯ (New analysis, Analysis log, this guide, keyboard shortcuts).
  • View list on the left: seven open-loop and seven closed-loop views. The closed-loop group is greyed out without a DISCON and shows a counter while it is computed.
  • Workspace: at the top, a row with the wind speeds (‹ › or ← →; the dot is the closed-loop verdict there) and below it that point's values in three groups: operating point (rotor, pitch, generator torque, power, TSR, Cp), controller (loop, Kp, Ki) and design model (A, B). The plots scroll below.
  • Status bar: what is running (with percentage), the folder in use (click to open it), the closed-loop verdict and the version.

Side panel on the right (panel icon in the top bar shows or hides it); its sections fold and stay as you left them:

  • View settings — the view's own choices (input and output, quick picks, channels, check boxes, max frequency);
  • Insights — a verdict line (green / amber / red) and tiles with the figures that matter. Transfer function: G(s) in factored form, steady-state gain and sign, bandwidth, dominant and lightly damped modes, the bandwidth limit set by right-half-plane zeros, modes not in this pair, pole / zero lists. Loop shape: margins against their targets (6 dB, 45°, sm 0.5), the limiting one, crossover and loop time constant, peak sensitivity, delay and disk margins, bandwidth and peak of T. Stability summary: stable or not at every wind speed, the weakest wind speed and the worst margins (click a tile to go to that wind speed), least-damped closed-loop mode, Nyquist check;
  • Results — the numbers of every plot, under the plot's name (click the name to jump to it); explanations are folded under "ⓘ Notes";
  • Plots — legend, cursor, grid, line width; In this view — jump to any plot or table; Data — one CSV with the curves of all plots in the view.

The middle then shows only plots and tables; a view with a single plot (Nyquist, Modes, Time response) uses the full height. With the panel closed the numbers are shown on the cards again (a red dot marks a value that needs attention). In a narrow window the panel floats over the plots.

Cursor. The box with the values of all curves appears only when the cursor is on a computed point; between points only the coloured tags show. Pointing at a plot shows dotted lines in both axes with the x and y values on the axes, and for each curve its value at the cursor, labelled at the right edge in the curve's colour (filled dot: a computed point; hollow dot: read off the line between points). Plots of the same x quantity follow along: on Operating points every wind-speed plot shows the same wind speed; Bode magnitude and phase share the frequency. Settings → Crosshair switches to a vertical line only, or off.

Search (Ctrl K) finds a view (also by words such as bode, margins, eigenvalues, hankel), a wind speed (type the number), an action (report, new analysis) or a quick setting (Hz, dark theme, legends, crosshair).

Move the pointer onto a plot and its tools appear: Enlarge (the plot — or both plots of a Bode diagram — as large as the window; Esc or Close returns), + / −, Box zoom, Reset, PNG / SVG / CSV. Curves are named in a boxed legend inside the axes. A plot with many curves (more than 6 by default) shows only ▸ N/M curves; click it for a scrolling list with all / none.

Open loop

Operating points

Trim values against wind speed (rotor speed, pitch, power, torque, TSR, Cp/Ct) and a table with the periodicity index before and after MBC. Check that the sweep is complete and the trim looks physical before reading anything else.

Campbell diagram

Every structural mode is tracked across wind speeds by mode shape (MAC), so lines do not jump where frequencies cross. Line and marker style show symmetry: collective, backward whirl or forward whirl. The 1P/3P/6P/9P lines are drawn, and the closest approach of any mode to 1P, 3P and 6P is reported. Below it is damping against wind speed, which is where aero-elastic instabilities show first.

Loop: open / closed. Closed shows the modes with the ROSCO controller in the loop at every wind speed. The open-loop tracks stay as thin grey lines, so you can see which modes the controller shifts or un-damps, and the controller's own modes (PI integrator, actuator, filters) are added. It needs a DISCON and is available once the closed loop has been computed.

Blade modes and whirl need blade DOFs in the linearisation (ElastoDyn FlapDOF/EdgeDOF or BeamDyn). A banner tells you when there are none.

Modes

Eigenvalues at one operating point in the s-plane, with ζ = 5 %, 20 % and 50 % guide lines, and a table of modes. Click a row for its participation factors: which physical DOFs make up the mode.

Transfer function

Bode diagram and pole-zero map for any input → output (quick-pick buttons for the usual control pairs). Reported: DC gain, peak, bandwidth, right-half-plane zeros (non-minimum phase; the pitch → generator-speed zero limits the achievable bandwidth), and poles cancelled by zeros (modes the input does not excite or the output does not see).

Time response

Exact step or impulse response of the linear model for any channel pair, with overshoot, rise and settling times. Pan right to run the response longer; it is recomputed as you go.

Across wind speeds

The same transfer function at every operating point on one Bode plot (dark = high wind), plus DC gain and resonance frequency against wind speed. Use it to see how much the plant changes over the gain schedule.

Controllability & Hankel

For a chosen set of inputs and outputs (the control set pitch + torque → generator speed, platform pitch, nacelle acceleration, or any single pair):

  • Kalman ranks: how many states are controllable and observable, the minimal order, and which modes are uncontrollable or unobservable. Stabilisable/detectable says whether every such mode is at least stable.
  • Controllability–observability plane: one point per mode. Bottom-left modes are hard to both excite and see, so a controller on these channels cannot damp them.
  • Eigenvalues by modal Hankel value: which modes dominate the input → output energy.
  • Hankel singular values: the energy ranking of the balanced states, and the order a reduced model needs for a given error bound.
  • The same measures across wind speeds.

Closed loop

The ROSCO controller rebuilt from DISCON.IN is closed around the linearisation at every operating point. The region is chosen from the trim: Region 3 (pitch PI) when the rotor is at rated speed, otherwise Region 2 (torque PI). You can override the region per point in the Stability summary table.

Stability summary

Stable/unstable at each point; gain margin, phase margin, stability margin sm = 1/‖S‖∞ and the least-damped closed-loop mode against wind speed; and a table with every number, including delay margin and the Nyquist check P → Z.

QuantityCommon guideMeaning
Gain margin≥ 6 dBhow much the loop gain can grow before instability
Phase margin≥ 30–45°extra phase lag (e.g. delay) tolerated at crossover
sm = min |1+L|≥ 0.4–0.5closest approach to −1; covers gain and phase at once
‖S‖∞≤ 6–8 dBlargest disturbance amplification
Disk marginabout ±6 dB / ±37°gain and phase off at the same time

Disk margin. "±5.5 dB and ±34°" means the loop stays stable when the gain is off by up to 5.5 dB and the phase by up to 34° at the same time. Gain and phase margins each assume only one of them is off, so the disk margin is smaller and closer to reality.

Loop delay [ms]. The controller runs once per time step, which acts like a delay in the loop. The default is 1.5 × DT when the .fst is given (half a step for the hold, one step for the controller call); otherwise type it, e.g. 37.5 for DT = 25 ms. Leave it empty for no delay. The charts get a dashed "with delay" curve, the table a PM with delay column, and the header says whether every point is still stable.

Pitch–torque interaction. Around rated wind speed both PI loops act on generator speed. The card closes both at once and compares with each loop alone: the phase margin of each loop with and without the other, the coupling in dB (how much the torque loop changes the gain the pitch loop sees at its crossover), and whether the combination is stable. Two integrators on one measurement always leave one pole at the origin; ROSCO's set-point smoother, which is not part of the linear model, decides which loop holds the speed.

Region → Both loops (R2½) in the table closes both loops at that wind speed for every closed-loop tab (loop shape, Nyquist, poles, gain study, time response).

Report

Report (page icon in the top bar) builds one self-contained HTML file: a summary verdict, inputs, warnings, operating points, open- and closed-loop Campbell diagrams, the stability table with margins (and delay, if set), gain headroom, pitch–torque interaction and the scope of the analysis. It opens in a new tab and is also downloaded; use Print / save as PDF in it. If the browser blocks the new tab, the downloaded file is the same.

Loop shape & Nyquist

|L|, ∠L, |S| and |T| with every crossover marked, and the Nyquist curve with the sm circle around −1. Use Near −1 and Fit all to change the Nyquist view.

Poles & root locus

Closed-loop poles (filled) over open-loop poles (hollow), labelled by participation (plant DOF or controller block). The root locus scales the whole loop gain by k; the first unstable k is the gain margin as a factor.

Gain study

Answers "what happens to stability if the gains change?" at the selected operating point and across wind speeds.

  1. Stability map. Each cell is one closed loop with Kp × x and Ki × y (factors on the DISCON gains; 1 × 1 is DISCON, marked ◆). Colour shows the damping of the speed-loop pole, the pole ROSCO places with ωpc/ζpc, or of the least-damped pole the gains can move. Red means some closed-loop pole is unstable. The thick line is the stability boundary; the dashed line is the ζ contour you choose.
  2. Click any cell (or type factors and press Analyse) to see those gains against DISCON: margins, sm, ‖S‖∞, speed-loop ωn/ζ, closed-loop poles, Nyquist near −1, and the step response of generator speed and pitch command to a 1 m/s wind step. Values outside the usual guides are shown in red.
  3. PI gain scaling across wind speeds. Both PI gains are scaled together by k at every operating point. The solid line is the largest stable k, the dashed line the smallest, and the table gives the gain headroom (20·log₁₀ kmax). Click a cell to open that wind speed and factor in the map above.

Options: vary Kp × Ki, or PI × floating (both PI gains against Fl_Kp) when floating feedback is on; the range (×0.5–2, ×0.25–4, ×0.1–10); resolution 15², 25² or 41²; and what the colour shows.

Modes the gains cannot move, because the actuator cannot excite them or the sensors cannot see them, are listed under the map. They are left out of the colour so they do not hide the effect of the gains. They still count towards stable/unstable.
Factors apply to the gains at this operating point. To carry a choice into DISCON, multiply the scheduled PC_GS_KP/PC_GS_KI near this pitch angle, then re-run the analysis to check every wind speed.

Time response

Closed- against open-loop response to a step or impulse on any plant input (wind by default), for a plant output or the controller command, plus the disturbance-rejection frequency response.

Controller & design

The pitch gain schedule (DISCON and YAML), the controller frequency response with every filter, and the ROSCO 1-DOF design model (A, B) from the linearisation, the Cp table and ROSCO's tuning. The ωn/ζ targets are compared with what the DISCON gains imply and what the full closed loop achieves.

Workflows

Is the turbine stable, and with what margin?

  1. Closed loop → Stability summary: any ✕? Worst GM, PM and sm, and at which wind speed.
  2. Open that wind speed → Poles: which mode is unstable or least damped (plant DOF or controller block)?
  3. Gain study → PI gain scaling: how much headroom each wind speed has, and whether the problem is too much or too little gain.
  4. If a structural mode is the problem, check Controllability & Hankel: a mode the controller cannot see or excite cannot be fixed by the PI gains.

Retuning the pitch loop at one wind speed

  1. Gain study, colour by speed-loop damping, contour at your target ζ (e.g. 0.7).
  2. Click candidate cells along the contour and compare GM, PM, sm and the pitch-command step (actuator effort).
  3. Check neighbouring wind speeds with ← →, then transfer the factors into the DISCON schedule and re-run.

Same wind speed, azimuths at different rotor speeds

All azimuth files of one wind speed should describe one equilibrium. If the rotor speed differs between them, LinBench keeps them together (a wind speed is split only when its azimuths repeat, i.e. two complete sets). It then diagnoses the difference from the rotor speed Ω, azimuth ψ and simulation time t in each header:

PatternTestMeaningWhat to do
driftΩ follows t (adjusted R² of Ω ~ a + b·t ≥ 0.8)rotor still accelerating; trim not convergedOpenFAST: CalcSteady = True, tighter TrimTol, or linearise later (LinTimes/TMax)
periodicΩ follows ψ (1P + 3P Fourier fit)tower-shadow / shear ripple of a converged periodic trimexpected; MBC already uses each file's own Ω
scatterneitherfiles from different runs or settingscheck the files' origin and inputs

Warning level: drift or scatter ≥ 0.5 % (peak to peak), periodic ≥ 2 %; a notice from 0.1 % (0.5 % for periodic). Where it shows:

  1. Setup scan table: the Rotor column shows ±spread, with the diagnosis in Notes.
  2. Run analysis log: a red WARNING line with the Ω range.
  3. Operating points tab → Rotor speed across the azimuth files: each file's rotor speed as a deviation (%) from the mean at its wind speed. The files of one wind speed are spread a little sideways in azimuth order (0° left, 360° right) and joined. A clean set is a flat line at 0; drift is a slope; 1P/3P ripple is a wave. The dashed lines at ±0.25 % mark the warning level for drift and scatter (0.5 % peak to peak); red = warning, amber = notice. The shaded strip is the selected wind speed.
  4. Rotor speed … in the order it was linearised: Ω against the simulation time in each file header, labelled by azimuth. A straight rising or falling line means the rotor was still accelerating: the trim had not converged, so the linearisations are not one equilibrium.
  5. Azimuth files table: each file's azimuth, time, Ω, ΔΩ, pitch, generator torque and generator speed. If pitch and torque also move between files, the controller was still acting during the sweep.
  6. Does it matter? Each azimuth file is also MBC-transformed on its own. The Δf / Δζ columns (largest change of any mode for that file) and the Mode frequency in each single-azimuth model chart show how far each mode would move if you trusted that one file instead of the average. Whirl modes react most, because their frequencies shift with ±Ω.

Try it on samples/rotor_speed_drift (17 m/s linearised while the rotor sped up by 3 %).

Checking a new linearisation set

  1. Run analysis page: periodicity after MBC should be small; a large value means an unexpected rotor setup or a missing azimuth.
  2. Operating points: is the trim smooth over wind speed?
  3. Campbell diagram: are there crossings with 1P/3P, or damping near zero?

Maths reference

Multi-blade coordinates (MBC)

Blade b is at ψb = ψ + 2π(b−1)/3. Each triplet of blade states maps to collective, cosine and sine components:

xrot = T(ψ) xnr,  T = [[T₁, 0], [Ω T₂, T₁]] (2nd-order DOFs),  T₁ rows = [1, cos ψb, sin ψb]
Anr = T⁻¹(A T − Ṫ),  Bnr = T⁻¹ B T1u,  Cnr = T1y⁻¹ C T,  Dnr = T1y⁻¹ D T1u

The model is then averaged over the N azimuths: Ā = (1/N) Σ Anr(ψk). Periodicity index = maxk ‖A(ψk) − Ā‖ / ‖Ā‖. Averaging removes the periodic part of the matrices; it does not limit the bandwidth of the averaged model. Reference: G. Bir, AIAA 2008-1300.

Modes

A vk = λk vk,  W = V⁻¹,  fn = |λ|/2π,  fd = |Im λ|/2π,  ζ = −Re λ/|λ|
participation pik = |wki vik| / Σi |wki vik|

Participation is summed per physical DOF (position, velocity and hydrodynamic states of the same DOF). For a cyclic rotor pair with components C (cos) and S (sin): forward whirl if |C + jS| ≫ |C − jS|, backward whirl if the reverse.

Mode tracking (Campbell)

MACij = |viᴴ vj|² / (‖vi‖²‖vj‖²),   cost = (1 − MAC) + 0.6 |ln(fj/fi)| + family penalty

Modes at neighbouring wind speeds are paired by the optimal (Hungarian) assignment on this cost.

Transfer functions

G(s) = c (sI − A)⁻¹ b + d = Σk rk/(s − λk) + d,   rk = (c vk)(wk b)

A mode with rk ≈ 0 is not excited or not observed; its pole is cancelled by a zero. Zeros are the finite generalised eigenvalues of [[A, b], [c, d]] on the significant modes. Plots in the browser use this pole/residue form. Each export is checked against the direct state-space result before it is used, so curves can be redrawn over any range.

Closed loop, margins and Nyquist

L(s) = −K(s) G(s) (loop broken at the actuator),  S = 1/(1 + L),  T = L/(1 + L)
GM: ∠L(jω) = −180°, GM = −1/Re L;   PM: |L(jω)| = 1;   sm = minω |1 + L(jω)|;   delay margin = PM/ωc
Nyquist: Z = N + P (Z closed-loop RHP poles, P open-loop RHP poles, N clockwise encirclements of −1)
Disk margin: α = 1/maxω|S(jω) − ½|;  gain within [1/g, g], g = (2+α)/(2−α), and phase within ±2·atan(α/2), together
Loop delay: Lτ(s) = L(s)·e−sτ, default τ = 1.5·DT;  each PM drops by ωcτ;  stability from Z = N + P on Lτ

Both loops: the torque PI (or the pitch PI) is kept closed as a secondary loop while the other is opened for L; coupling = −20·log₁₀|1 + Ltorque(jωc)| dB. Closed-loop Campbell: modes of the closed-loop A, labelled from the most similar open-loop mode shape (MAC) or from the controller block, and tracked like the open-loop modes.

Crossings are found by root-finding on the exact L(jω), not read from a grid. Stability is decided from the eigenvalues of the closed-loop A and cross-checked with the Nyquist count.

Controllability, observability, Hankel singular values

PBH: mode k uncontrollable ⇔ wk B = 0;  unobservable ⇔ C vk = 0
ck = |wkB| / (|wk||B|),  ok = |Cvk| / (|C||vk|)  (Hamdan–Nayfeh angle measures)
A Wc + WcAᵀ + BBᵀ = 0,  AᵀWo + WoA + CᵀC = 0,  σi = √λi(WcWo)

Ranks come from the orthogonal staircase (Kalman decomposition), not from the ill-conditioned matrix [B AB A²B …]. HSVs are computed for the stable part; unstable modes are split off first (ordered Schur form + Sylvester equation) and counted separately. Balanced truncation to order r has H∞ error ≤ 2 Σi>r σi.

Gain study

Acl(kpKp, kiKi) → λj;  stable ⇔ max Re λj ≤ 0

Speed-loop pole: the closed-loop pole below 0.5 Hz with the largest participation of the rotor-speed state and the PI integrator. Least-damped moved pole: min ζ over closed-loop poles below 2 Hz that differ from every open-loop pole. The PI-scaling limits are refined by bisection; with no floating feedback, the upper limit equals the gain margin as a factor. ROSCO's design rule on the 1-DOF model ω̇ = Aω + Bβ:

Kp = (2ζωn + A)/B,   Ki = ωn²/B

Limits of the linear model

  • Small perturbations about each trim point: no saturation, rate limits, set-point smoothing, peak shaving or wind-speed estimator dynamics.
  • The controller is continuous-time. Its time step is represented only by the optional loop delay in the Stability summary; filter discretisation is not modelled.
  • Azimuth averaging assumes a close-to-isotropic rotor. Check the periodicity index after MBC.
  • Near rated (Region 2½) both loops may be active or saturated. Use the region override and treat these points with care.

Speed tips

  • Results are cached: going back to a tab, an operating point or a gain map you already opened is instant.
  • Start the gain study at 25² and switch to 41² only for the final picture.
  • Plots use fewer points while you drag and full detail when you release.
  • Large sets (hundreds of files): reading and MBC is the longest step, as the Run analysis page shows. Put only the wind speeds you need in the folder.
